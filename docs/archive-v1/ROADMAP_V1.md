# Sandle Archive v1 — 단계별 작업 계획서

상태: 운영 기준 v1
작성: 2026-09-01

## 0. 운영 규칙

이 문서는 Archive v1 작업의 마스터 순서표다. GPT와 Claude는 작업 시작 시 `AGENTS.md` → `docs/AI_WORKFLOW.md` → `docs/WORK_STATUS.md` → 이 문서 순으로 확인한다.

- 큰 단계는 `1`, `2`, `3`처럼 고정한다.
- 실제 작업은 `1.1`, `1.2`, `1.3`처럼 작은 단위로 기록한다.
- 사용자 피드백 수정도 기존 번호를 덮어쓰지 않고 다음 소번호로 기록한다.
- 큰 단계가 끝나고 다음 단계로 넘어가기 전에는 완료한 것 / 남은 것 / 보류한 결정 / 다음 단계 세부작업을 사용자에게 먼저 보여준다.
- **사용자가 큰 단계 전체 진행을 승인하면, 계획된 소단계는 중간 컨펌 없이 다음 사용자 검토 지점까지 이어서 구현한다.** 세부 버튼·문구마다 확인받는 나노매니징을 피한다.
- 다만 보안·권한·데이터 모델 변경, 원본 훼손 가능성, 큰 구조변경처럼 되돌리기 어려운 결정은 중간 확인할 수 있다.
- `done`은 사용자 확인까지 끝난 상태에만 사용한다. 코드가 존재하는 것과 사용자가 실제로 테스트 가능한 것은 구분한다.
- Archive와 충돌하지 않는 별도 예약 업무는 병행할 수 있다.
- 상태는 `planned / in_progress / review / blocked / done`을 사용한다.
- UI 표시 순서와 데이터 구조는 분리한다. 화면 구성 변경이 데이터 재이관으로 이어지지 않게 한다.

# 2. 관리자 입력·검토 흐름 확정

현재 상태: `review` — 2.5 전체 검토

사용자 요청: 2단계는 소단계마다 확인받지 않고 전체를 먼저 연결한 뒤 한 번에 수정한다.

사용자 피드백(2.5 시작 직후): 기존 화면은 2.2·2.3·2.4가 각각 무엇인지 직접 시험하기 어렵고, 실제로 테스트할 것이 없는 것처럼 보였음. 따라서 2.2~2.4를 번호별로 명확하게 진입하고 조작할 수 있는 화면으로 보강함.

### 2.1 관리자 영역 화면 — `review`

- 공개 Archive와 분리된 `/archive-v1/admin/`
- 좌측 관리 메뉴
- 회의 작성은 기존 회의록 시스템으로 연결
- 사용자 전체 검토가 끝나기 전까지 `done`으로 확정하지 않음

### 2.2 AI 새 자료 등록 흐름 — `review` (테스트 가능)

- 좌측 메뉴에 `2.2 새 자료 등록`을 명시
- 최소 입력: 제목 / 자료종류 / 날짜 / 적용범위 / 공개등급 / 원본위치 / 메모
- `예시 채우기` → `AI 초안 만들기 · 시뮬레이션`을 직접 눌러볼 수 있음
- 실제 AI 호출 대신 규칙 기반 시뮬레이션으로 주제·조직·현행상태·관계 후보 생성
- 생성된 초안은 실제 분류 검토 목록으로 이동
- 실제 목표는 GPT/Claude가 문서를 읽고 이 초안을 자동 생성하는 것

### 2.3 공개 등급 — `review` (전용 테스트 화면 추가)

- 좌측 메뉴에 `2.3 공개 등급` 전용 화면 추가
- 샘플 자료마다 `public / resident / private`를 직접 변경 가능
- 변경 즉시 `공개 빌드 포함 / 공개 빌드 제외 / 모든 공개 빌드 제외` 결과를 보여줌
- 발행 대기 화면에서도 최종 공개등급을 다시 바꿀 수 있음

보안 원칙:

- `public`: 인터넷 공개 가능
- `resident`: 입주민 인증 필요
- `private`: 관리자 내부
- resident/private는 UI 숨김으로 보호하지 않는다.
- 실제 인증 전에는 해당 원본·검색본문을 공개 GitHub Pages 빌드에 포함하지 않는다.
- 실제 인증/저장 연결은 4단계에서 확정한다.

### 2.4 분류·관계 검토함 + 발행 대기 — `review` (테스트 가능)

분류 검토:
- AI 추천 주제 / 조직 / 현행상태 / 신뢰도 확인
- 직접 수정 / 승인 / 보류 / 보류 해제

관계 검토:
- 연결 대상 / 관계 종류 / 근거 수준 확인
- `explicit / verified / inferred`
- 직접 수정 / 승인 / 연결 없이 진행

발행 대기:
- 분류·관계 검토가 끝난 자료만 노출
- 공개등급 최종 확인
- 자료 미리보기
- 프로토타입 발행 처리

현재 `발행`은 브라우저 메모리에서만 상태를 바꾸며 실제 GitHub/Drive/검색 인덱스에 쓰지 않는다.

### 2.5 사용자 전체 검토 — `review`

관리 작업대 첫 화면에서 `2.2 직접 테스트 / 2.3 직접 테스트 / 2.4 분류 / 2.4 관계`를 각각 바로 열 수 있게 함.

빠른 전체 테스트:

`2.2 예시 채우기 → AI 초안 만들기 → 2.4 분류 승인 → 2.4 관계 승인 또는 생략 → 발행 대기 → 공개등급 확인 → 미리보기 발행`

확인할 것:
- 각 소단계가 실제로 테스트 가능한지
- 별도 관리자 화면이 자연스러운가
- 왼쪽 메뉴가 과하거나 부족한가
- 직접 입력 항목이 너무 많은가
- 분류 검토와 관계 검토를 나누는 것이 이해하기 쉬운가
- 공개등급 선택 시점이 적절한가
- 검토 → 발행 대기까지 너무 번거롭지 않은가
- 회의 작성이 중복 입력 없이 유지되는가
