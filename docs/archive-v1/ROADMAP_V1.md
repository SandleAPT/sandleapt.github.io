# Sandle Archive v1 — 단계별 작업 계획서

상태: 운영 기준 v1
작성: 2026-09-01

## 0. 이 문서의 역할

이 문서는 Archive v1 작업의 **마스터 순서표**다.
GPT와 Claude는 Archive v1 작업을 시작할 때 이 문서를 확인하고, 현재 번호의 작업만 진행한다.

핵심 규칙:

- 큰 단계는 `1`, `2`, `3`처럼 번호를 고정한다.
- 실제 작업은 `1.1`, `1.2`, `1.3`처럼 작은 단위로 늘려간다.
- 사용자 피드백으로 수정이 생기면 기존 번호를 억지로 덮어쓰지 않고 다음 소번호를 추가한다.
  - 예: `1.2` 결과를 본 뒤 수정 요청이 나오면 `1.3 피드백 반영`, 이후 기존 예정 작업은 `1.4`로 밀어 기록한다.
- 각 큰 단계는 사용자가 결과를 보고 방향을 승인해야 `done`으로 바꾼다.
- Archive v1에서는 **1단계가 완료되기 전 2단계의 본작업을 시작하지 않는다.**
- 단, Claude가 맡은 기존 회의록/입대의 데이터 작업처럼 Archive v1과 충돌하지 않는 별도 업무는 병행할 수 있다.
- 구조·검색 순서·입력 방식·권한 방식이 바뀌는 결정은 반드시 사용자 확인을 거친다.
- 단순 오탈자, 기존 규칙에 따른 추가 데이터, 이미 승인된 UI의 소규모 보완은 자율 처리할 수 있으나 작업 로그에 남긴다.

상태 표기:

- `planned` — 아직 시작하지 않음
- `in_progress` — 현재 작업 중
- `review` — 결과를 만들었고 사용자 확인 대기
- `blocked` — 자료/권한/사용량 등으로 대기
- `done` — 사용자 확인까지 끝남

# 1. Archive 탐색·검색 화면 방향 확정

목표: 주민이 Archive를 처음 열고 검색했을 때 무엇을 먼저 보고 어떻게 과거와 현재를 따라가는지 확정한다.

현재 상태: `in_progress`

### 1.1 Golden Sample 주제 화면 제작 — `done`

- `archive-v1/` 시험판 생성
- 헬스장·GX 예시
- 작은도서관 예시
- 현재 기준 → 흐름 → 관련 기록 형태 시험
- 사용자가 기본 방향이 맞다고 확인

### 1.2 Archive 첫 화면 제작 — `planned`

첫 화면에서 시험할 요소:

- 통합검색
- 많이 본 주제 TOP 5
- 최근 추가/변경 기록
- 샘플 주제 바로가기
- 현재 시험판임을 명확히 표시

TOP 5는 실제 조회 데이터가 충분히 쌓이기 전에는 샘플/임시값으로 표시하고, 측정값인 것처럼 오인시키지 않는다.

### 1.3 검색 결과안 A 제작 — `planned`

구성안:

`현재 기준 → 주요 흐름 → 관련 기록`

### 1.4 검색 결과안 B 제작 — `planned`

구성안:

`현재 기준 → 핵심 요약 → 타임라인 → 자료 전체`

### 1.5 사용자 비교 검토 — `planned`

사용자가 실제 화면을 보고 다음을 결정한다.

- A/B 중 어느 쪽이 더 자연스러운지
- 둘을 섞을지
- TOP 5 위치
- 검색 결과 정보 밀도
- 모바일에서 가장 먼저 보여야 할 정보

### 1.6 피드백 반영 및 1단계 확정 — `planned`

필요한 수정 횟수만큼 `1.6`, `1.7`, `1.8`처럼 소번호를 늘릴 수 있다.

완료 조건:

- 사용자가 Archive 첫 화면과 검색 결과의 큰 방향을 승인
- 이후 검색 UI의 대규모 구조변경은 재승인 대상으로 관리

# 2. 관리자 입력·검토 흐름 확정

목표: 새 자료를 추가할 때 사용자가 데이터베이스를 직접 관리하지 않아도 되도록 한다.

상태: `planned`

### 2.1 관리자 영역 화면 샘플

기본 메뉴 후보:

- 회의 작성
- 새 자료 등록
- 분류 검토
- 관계 검토
- 발행 대기

### 2.2 AI를 통한 새 자료 등록 흐름

기본 전제:

- 사용자는 보통 GPT/Claude에게 "이 자료 추가해줘"라고 요청
- AI가 제목, 날짜, 자료종류, 주제, 조직, 관계 후보를 작성
- 바로 공개하지 않고 `발행 대기`로 저장

### 2.3 공개 등급 적용

확정된 등급:

- `public`
- `resident`
- `private`

화면과 데이터 양쪽에서 같은 의미를 사용한다.

### 2.4 분류·관계 검토함 샘플

사용자는 애매한 항목만 빠르게 승인/수정할 수 있어야 한다.

### 2.5 사용자 검토

확인할 것:

- 직접 입력해야 할 항목이 너무 많지 않은지
- AI 자동분류를 어느 정도까지 믿고 맡길지
- 발행 전 검토 단계가 번거롭지 않은지
- 공개등급 선택 방식이 이해하기 쉬운지

### 2.6 피드백 반영 및 2단계 확정

완료 조건:

- 새 자료 등록 → AI 분석 → 검토 → 발행 흐름 승인

# 3. 회의록 작성 기능과 Archive 연결

목표: 현재 회의록 작성 기능의 장점을 살리면서 같은 내용을 Archive에 다시 입력하지 않게 한다.

상태: `planned`

### 3.1 현행 회의록 작성 구조 확인

특히 유지해야 할 조건:

- 회의 설정
- 안건
- 발언/결정 내용
- 수기 입력 가능
- 안건별 출력/확인
- 최종 회의록은 가능한 한 1페이지 안에 정리

### 3.2 기존 회의 데이터 → Archive 필드 매핑

예:

- 회의 1건 → Document
- 안건 1건 → Fragment
- 의결 결과 → Action / Relation
- 관련 주제 → Topic

### 3.3 수기 회의 작성 화면 프로토타입

회의 중 실제로 빠르게 적을 수 있는지가 우선이다.
Archive 메타데이터 때문에 회의 작성이 복잡해지면 안 된다.

### 3.4 Archive 초안 자동 생성

회의록 저장 시:

- Archive Document 생성
- 안건 Fragment 생성
- 주제/관계 후보 생성
- 검토 필요 항목만 발행 대기로 이동

### 3.5 1페이지 출력 검증

Archive 연결 때문에 기존 회의록 1페이지 출력성이 깨지지 않는지 확인한다.

### 3.6 사용자 실사용 검토

### 3.7 피드백 반영 및 3단계 확정

완료 조건:

- 회의 작성과 Archive 등록을 한 번의 입력 흐름으로 처리 가능
- 1페이지 회의록 운영 방식 유지
