# Sandle Archive v1 — 단계별 작업 계획서

상태: 운영 기준 v1
작성: 2026-09-01

## 0. 운영 규칙

이 문서는 Archive v1 작업의 마스터 순서표다. GPT와 Claude는 작업 시작 시 `AGENTS.md` → `docs/AI_WORKFLOW.md` → `docs/WORK_STATUS.md` → 이 문서 순으로 확인한다.

- 큰 단계는 `1`, `2`, `3`처럼 고정한다.
- 실제 작업은 `1.1`, `1.2`, `1.3`처럼 작은 단위로 진행한다.
- 사용자 피드백 수정도 기존 번호를 덮어쓰지 않고 다음 소번호로 기록한다.
- 각 큰 단계는 사용자 승인 전 다음 큰 단계로 넘어가지 않는다.
- Archive와 충돌하지 않는 별도 예약 업무는 병행할 수 있다.
- 구조·검색 순서·입력 방식·권한 방식 변경은 사용자 확인 대상이다.
- 상태는 `planned / in_progress / review / blocked / done`을 사용한다.
- UI의 표시 순서와 데이터 구조는 분리한다. 화면 구성 변경이 데이터 재이관으로 이어지지 않게 한다.

# 1. Archive 탐색·검색 화면 방향 확정

목표: 주민이 처음 들어와 주제를 훑고 검색한 뒤 현재 기준과 과거 기록을 자연스럽게 따라가게 한다.

현재 상태: `in_progress`

### 1.1 Golden Sample 주제 화면 — `done`

- `/archive-v1/` 시험판 생성
- 헬스장·GX, 작은도서관 샘플
- 현재 기준 → 흐름 → 관련 기록 구조 시험

### 1.2 Archive 첫 화면 — `done`

- 통합검색
- TOP5 샘플
- 최근 추가·변경 기록
- 주제 바로가기

피드백: 인기순위보다 전체 주제를 편하게 훑는 구조가 우선이고, 긴 데이터는 화면을 무한히 늘리지 않아야 함.

### 1.3 1.2 피드백 반영 — `done`

- TOP5 제거 후 랜덤 주제 방식 시험
- 현재 기준 3건 / 주요 흐름 4건 / 관련 기록 6건 기본 미리보기
- 초과 자료 `전체 N건 보기`
- 카드·타임라인·기록 클릭 상세 팝업
- 긴 설명 2줄 안팎으로 제한

피드백: 일부 랜덤 노출이 아니라 전체 주제를 모두 보여주고 찾기 쉽게 정렬하는 편이 좋음.

### 1.4 1.3 피드백 반영 — `done`

- 공개 가능한 전체 주제 표시
- 한국어 가나다순 정렬
- 주제 패널이 과도하게 길어지는 문제 보완

피드백: 주제마다 큰 카드가 아니라 큰 주제명이 한눈에 들어오는 밀도가 좋음.

### 1.5 1.4 피드백 반영 — `done`

- 전체 주제를 **가나다순 텍스트형 버튼 모음**으로 변경
- 설명·화살표·점 아이콘 제거
- 주제명 사이 작은 구분점(`·`)
- 화면 폭에 따라 자연스럽게 줄바꿈
- 각 주제명 클릭 시 기존 주제 상세로 이동

### 1.6 검색 결과안 A — `done`

구성: `현재 기준 → 주요 흐름 → 관련 기록`

- 검색창에서 샘플 주제를 검색하면 A안 전용 결과 화면 표시
- 현재 기준을 먼저, 과거 흐름을 다음, 원자료 목록을 마지막에 배치
- 현재 기준 3건 / 주요 흐름 4건 / 관련 기록 6건 기본 표시
- 개별 항목 상세 팝업과 `주제 전체 보기` 연결
- A안 전용 스타일 `archive-v1/assets/search-a.css`

### 1.7 검색 결과안 B — `done`

구성: `현재 기준 → 핵심 요약 → 타임라인 → 자료 전체`

- 검색 기본 화면을 B안으로 시험
- 같은 검색어에서 `A안 / B안` 즉시 전환 가능
- B안 1단계: 현재 기준
- B안 2단계: 주제 설명, 현재 기준, 최근 흐름, 연결 기록을 바탕으로 핵심 요약
- B안 3단계: 타임라인
- B안 4단계: 자료 전체 목록
- 자료가 많아질 경우 화면 폭주를 막기 위해 미리보기 상한과 `주제 전체 보기` 사용
- B안 전용 스타일 `archive-v1/assets/search-b.css`
- `archive-v1/config/search-layouts.js`에 A/B section 순서와 preview 개수를 별도 설정
- `docs/archive-v1/UI_COMPOSITION_V1.md`에 조립식 UI 원칙 기록

사용자 결정: A/B 최종 선택은 전체 기능 흐름을 더 본 뒤 나중에 결정한다. 1단계에서 특정 검색 레이아웃을 고정하지 않는다.

### 1.8 전체 동작 흐름 검토 — `review`

목표: A/B 취향을 고르는 단계가 아니라 Archive의 기본 동선이 전체적으로 이어지는지 확인한다.

검토 흐름:

`첫 화면 → 전체 주제 → 주제 상세 → 검색 A/B → 개별 기록 상세 → 다시 탐색`

구현 내용:

- 미리보기 화면에 `1.8 전체 흐름 점검` 전용 내비게이터 추가
- `첫 화면 / 주제 상세 / 검색 A / 검색 B / 상세 팝업`을 한 번에 시험 가능
- 검토 도구는 `archive-v1/review-1-8.js`, `archive-v1/assets/review-1-8.css`로 분리해 실제 운영 UI와 독립
- A/B 선택은 보류하고 두 화면 모두 유지
- 검색 구성은 데이터가 아니라 설정·renderer 계층에서 교체하는 원칙 유지

사용자 확인 포인트:

- 홈에서 원하는 정보로 들어가는 동선이 끊기지 않는지
- 주제 탐색과 직접 검색이 모두 자연스러운지
- 검색 결과에서 개별 기록 상세까지 접근 가능한지
- 뒤로 돌아가거나 다른 주제로 이동할 때 막히는 지점이 없는지
- 이후 관리자 입력 기능을 붙일 수 있는 전체 골격으로 보이는지

### 1.9 1단계 임시 확정 — `planned`

A/B 최종 선택 없이도 1단계를 임시 확정할 수 있다.

완료 조건:

- 첫 화면·주제 탐색·검색·상세 동선의 큰 흐름을 사용자 승인
- A/B 또는 혼합 레이아웃은 이후 실제 데이터와 다른 기능을 붙여본 뒤 config 변경으로 결정 가능
- 검색 레이아웃 변경이 데이터 재이관을 요구하지 않는 구조 유지

필요하면 `1.10`, `1.11`처럼 추가한다.
