# Sandle Archive v1 — Storage Plan

상태: 초안 v1

## 1. 결론

Archive v1은 GitHub를 **코드·메타데이터·검색용 텍스트·관계 인덱스** 중심으로 사용하고, 원본 PDF·사진·영상·대용량 스캔은 원칙적으로 Google Drive 같은 외부 저장소에 둔다.

GitHub Pages는 게시된 사이트 크기 자체가 1GB 이하라는 제한이 있으므로, 원본 문서를 계속 저장소 안에 누적하는 방식은 장기 아카이브에 적합하지 않다.

## 2. GitHub에 둘 것

- HTML/CSS/JS 등 화면 코드
- taxonomy / schema / relation 정의
- 문서 메타데이터 JSON
- 검색 인덱스
- 문서에서 추출한 검색용 텍스트 또는 요약
- 작은 썸네일·아이콘 등 꼭 필요한 정적 자산
- AI 작업지침·작업현황·이관 로그

## 3. Google Drive 등에 둘 것

- 원본 PDF
- HWP/DOCX/XLSX/PPTX 등 원본 오피스 문서
- 스캔 이미지
- 사진 묶음
- 녹음·영상
- 용량이 큰 판결문/설계도/도면 원본
- 동일 문서의 고해상도 보존본

GitHub에는 파일 자체 대신 아래 정보만 저장한다.

```json
{
  "source": {
    "storage": "google_drive",
    "file_id": "...",
    "url": "...",
    "mime": "application/pdf",
    "bytes": 12345678,
    "sha256": "..."
  }
}
```

`sha256`는 같은 원본인지 확인하거나 중복 업로드를 찾는 용도로 권장한다.

## 4. 검색은 원본 파일에 의존하지 않는다

통합검색 때마다 Google Drive의 PDF를 직접 읽는 구조로 만들지 않는다.

원본을 등록할 때 한 번 분석하여 다음을 GitHub 쪽 검색 데이터에 남긴다.

- 제목
- 날짜
- 자료종류
- 주제
- 조직
- 상태
- 안건/조문 등 Fragment
- 검색용 본문 텍스트 또는 필요한 범위의 추출문
- 요약
- 관계

따라서 사용자는 GitHub Pages에서 빠르게 검색하고, 원본 확인이 필요할 때만 Drive 원문을 연다.

## 5. 저장소 내부 목표 용량

GitHub의 최대치까지 쓰는 것을 목표로 하지 않는다.

Archive v1 운영 목표:

- `sandleapt.github.io` 소스 저장소: 가능하면 500MB보다 훨씬 아래 유지
- Archive 데이터/검색 인덱스: 처음에는 100~250MB 이내를 장기 경계선으로 관찰
- 개별 JSON은 작게 분할
- 단일 디렉터리에 파일을 과도하게 몰지 않음
- 원본 바이너리 신규 적재는 기본 금지

실제 데이터 증가 속도를 본 뒤 경계값은 조정한다.

## 6. 파일 크기 운영 규칙

- PDF/이미지/영상은 크기와 관계없이 원본 보존본은 Drive 우선
- GitHub에 새 바이너리를 추가하기 전 반드시 필요성을 검토
- 생성 가능한 파생물은 원본 저장소에 누적하지 않음
- 검색 텍스트가 너무 크면 연도/문서/fragment 단위로 분할
- 검색 인덱스도 하나의 거대한 JSON으로 만들지 않음

## 7. Git LFS를 Pages 원본 저장 해결책으로 쓰지 않는다

Git LFS는 큰 파일 관리 기능이지만 GitHub Pages 사이트에서는 LFS를 사용할 수 없으므로, Archive v1의 원본 문서 저장 해결책으로 채택하지 않는다.

## 8. 원본 링크가 깨지는 문제 대비

Drive 파일 이동·권한 변경으로 링크가 깨질 수 있으므로 메타데이터에 최소한 다음을 남긴다.

- 외부 저장소 종류
- 안정적인 file ID
- 원래 파일명
- MIME type
- 파일 크기
- 체크섬
- 등록일
- 마지막 링크 확인일

향후 링크 점검 배치를 만들 수 있다.

## 9. 현재 상태 참고

2026-09-01 확인 기준 GitHub API의 repository `size` 값은 다음과 같다.

- `SandleAPT/sandleapt.github.io`: 약 168KB 수준
- `SandleAPT/minutes`: 약 6.5MB 수준

현재는 용량 압박이 전혀 큰 상태가 아니지만, 앞으로 PDF·사진·계약서 원본까지 10년 이상 누적하면 구조가 달라지므로 지금부터 원본/색인을 분리한다.

## 10. 등록 흐름

권장 흐름:

원본 확보
→ Drive 원본 저장
→ 문서 ID 발급
→ 메타데이터/검색 텍스트 생성
→ GitHub Archive 데이터에 등록
→ 관계 연결
→ 화면/검색에서 노출
→ 필요 시 원본 열기

이 구조를 쓰면 GitHub는 가벼운 검색·표시 계층으로 유지하면서 원본 자료는 별도 보존할 수 있다.
