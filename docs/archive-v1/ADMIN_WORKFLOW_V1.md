# Sandle Archive v1 — 관리자 작업 흐름 v1

상태: 2단계 프로토타입 / 사용자 전체 검토 대기
작성: 2026-09-01

## 1. 운영 원칙

2단계는 세부 화면 하나씩 사용자에게 확인받기보다 **전체 업무 흐름을 먼저 연결한 뒤 한 번에 검토**한다.

목표는 관리자가 Archive를 유지하기 위해 데이터베이스 운영자가 되는 것이 아니라,

`자료 입력 또는 AI 요청 → 초안 → 애매한 것만 검토 → 공개범위 확인 → 발행`

만 빠르게 처리하는 것이다.

## 2. 관리 화면 위치

공개 Archive와 관리 도구를 분리한다.

- 공개 화면: `/archive-v1/`
- 관리 작업대: `/archive-v1/admin/`

관리 작업대는 별도 화면이며 좌측 메뉴에서 다음 업무를 오간다.

- 전체 흐름
- 새 자료 등록
- 분류 검토
- 관계 검토
- 발행 대기
- 회의 작성 연결

## 3. 2.2 새 자료 등록

최소 입력값:

- 자료 제목
- 자료 종류
- 날짜
- 적용 범위
- 공개 등급
- 원본 위치
- 간단 메모

실제 운영 목표는 사용자가 GPT/Claude에게 자료 추가를 요청하면 AI가 이 초안을 만들어 `needs_review` 상태로 넣는 것이다.

현재 정적 미리보기에서는 실제 AI/API 호출 대신 간단한 규칙 기반 시뮬레이션으로 주제·조직·현행상태·관계 후보가 생성되는 흐름만 검증한다.

사용자가 JSON이나 태그를 직접 관리하는 방식은 목표가 아니다.

## 4. 2.3 공개 등급

자료 단위로 다음 세 값을 사용한다.

- `public`: 인터넷 방문자에게 공개 가능
- `resident`: 인증된 입주민에게만 공개
- `private`: 관리자 내부 자료

중요한 보안 원칙:

- `resident`와 `private`는 단순히 화면에서 숨기는 방식으로 보호하지 않는다.
- 실제 인증 구조가 생기기 전에는 해당 원본과 검색 본문을 공개 GitHub Pages 빌드에 포함하지 않는다.
- 현재 2단계 화면에서는 공개등급을 메타데이터와 업무 흐름으로만 시험한다.

## 5. 2.4 분류 검토

AI 추천값 예:

- 큰 주제
- 관련 조직
- 현행/과거 상태
- 신뢰도

검토 원칙:

- 확신이 높은 기존 분류를 사람이 처음부터 다시 태깅하지 않는다.
- 애매한 항목만 승인 / 수정 / 보류한다.
- 보류 자료는 전체 발행 흐름에서 잠시 제외하고 나중에 다시 검토할 수 있다.

## 6. 관계 검토

관계 후보에는 다음을 같이 본다.

- 연결 대상
- 관계 종류
- 근거 수준

관계 예:

- `based_on`
- `follow_up_to`
- `implements`
- `contract_for`
- `supersedes`
- `amends`
- `related_to`

근거 수준:

- `explicit`: 문서에 관계가 명시됨
- `verified`: 별도 확인으로 관계가 확인됨
- `inferred`: 내용상 추정되는 관계

`inferred`는 검토 없이 사실처럼 확정하지 않는다. 관계가 불필요하거나 애매하면 `연결 없이 진행`할 수 있다.

## 7. 발행 대기

분류 검토가 끝나고 관계가 승인 또는 생략된 자료만 발행 대기에 들어간다.

발행 전에 확인:

- 제목
- 자료 종류
- 날짜
- 주제
- 관계
- 공개 등급
- 원본 위치

현재 프로토타입의 `발행` 버튼은 브라우저 메모리 안에서만 상태를 바꾼다. 실제 GitHub/Drive/검색 인덱스에는 쓰지 않는다.

## 8. 회의 작성

회의는 Archive 관리 화면에서 다시 작성하지 않는다.

기존 회의 작성 화면:

- 회의 설정
- 동대표 명단
- 안건·발언

을 그대로 사용한다.

3단계에서 회의 저장 결과를 Archive의 Document / Fragment / Topic / Relation 후보로 변환하는 adapter를 붙인다.

## 9. 프로토타입 파일 구조

한 파일에 기능을 몰지 않고 역할별로 나눈다.

- `archive-v1/admin/store.js`

## 10. 2단계에서 아직 하지 않은 것

아래는 의도적으로 실제 연결을 보류한다.

- 실제 관리자 인증
- GitHub/Drive 쓰기 API
- resident 인증
- 실제 AI 호출
- 실제 공개 검색 인덱스 갱신
- 실제 원본 업로드

이 항목은 3~4단계의 회의 연결, 저장소, 권한 구조와 함께 설계해야 안전하다.

## 11. 사용자 검토 포인트

2.5에서는 개별 버튼 디자인보다 전체 흐름을 우선 본다.

- 관리 화면을 별도로 두는 것이 자연스러운가
- 왼쪽 메뉴 구성이 과하거나 부족한가
- 새 자료 등록 때 직접 입력할 항목이 너무 많은가
- 분류 검토와 관계 검토를 분리하는 것이 이해하기 쉬운가
- 공개등급 선택 시점이 적절한가
- 발행 대기까지 이동하는 흐름이 지나치게 번거롭지 않은가
- 회의 작성이 별도 중복 입력 없이 유지되는가

사용자 피드백을 모아 2.6에서 한 번에 반영한 뒤 2단계를 확정한다.
