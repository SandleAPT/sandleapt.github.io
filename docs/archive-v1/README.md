# Sandle Archive v1

## 목표

산들마을의 과거 기록과 현재 기준을 하나의 검색·연결 구조에서 볼 수 있는 통합 아카이브를 만든다.

핵심 질문은 다음과 같다.

- 과거에 무엇이 논의되었는가?
- 어떤 결정을 했는가?
- 그 결정은 어떤 규약·운영규정·계약·공고와 연결되는가?
- 현재 적용되는 기준은 무엇인가?
- 이후 어떤 결과와 후속 조치가 있었는가?

## v1의 범위

초기 대상 자료:

- 입주자대표회의 회의록 및 안건
- 선거·선거관리위원회 기록
- 관리규약과 개정본
- 주차장·도서관·헬스장 등 운영규정
- 계약서·협약서·보험증권
- 공고·공문
- 회계·관리비·잡수입 관련 자료
- 하자·판결·조정 관련 자료

## 기본 원칙

1. 검색이 중심이고 메뉴는 탐색 보조수단이다.
2. 자료 한 건을 여러 메뉴에 복제하지 않는다.
3. 문서 종류, 주제, 주체, 시점, 상태, 행위, 관계를 서로 다른 축으로 관리한다.
4. 현재 적용 기준과 과거 기록을 명확히 구분한다.
5. 회의록은 문서뿐 아니라 안건 단위로 검색·연결할 수 있게 한다.
6. 규약은 버전뿐 아니라 조문 단위 연결을 고려한다.
7. 선거·계약·규정 변경 등은 개별 문서 묶음이 아니라 하나의 사건 흐름으로 연결할 수 있게 한다.
8. 큰 JSON 하나에 데이터를 몰지 않는다.
9. 현재 운영 사이트는 Archive v1이 충분히 검증될 때까지 유지한다.
10. 기존 데이터를 한 번에 변환하지 않는다. 작은 샘플을 승인받은 뒤 작은 배치로 이어달리기식 이관한다.
11. 원본 PDF·사진·영상 등 대용량 바이너리는 GitHub Pages에 계속 누적하지 않고 외부 저장소를 우선한다.

## 미리보기

- 구조 검증용 UI: `https://sandleapt.github.io/archive-v1/`
- 현재는 Golden Sample 수준의 일부 예시 데이터만 들어 있다.
- 전체 자료를 이관한 화면이 아니며, 사용자 피드백으로 구조를 확정하기 위한 시험판이다.

## 설계 문서

- `DATA_MODEL_V1.md` — 공통 레코드와 관계 구조
- `TAXONOMY_V1.md` — 분야·자료종류·주체·행위·상태 분류체계
- `MIGRATION_V1.md` — 샘플링·검증 게이트·작업량 제한·본 이관 계획
- `BATCH_TEMPLATE.md` — GPT/Claude 교대용 배치 작업·인계 템플릿
- `STORAGE_V1.md` — GitHub/Google Drive 역할 분담과 용량 관리 원칙
- 향후 `SEARCH_V1.md` — 통합검색과 주제 페이지 상세 규칙

## 구현 순서

1. 데이터 모델 초안
2. taxonomy 초안
3. 샘플링·이관 계획 확인
4. 단일 주제 Golden Sample UI 제작
5. 사용자가 실제 화면을 보고 구조 피드백
6. 검색/저장 구조 보완
7. 성격이 다른 소수 주제로 추가 검증
8. 작은 배치 단위 실제 이관
9. 기존 기능 연결
10. 충분한 검증 후 `sandleapt.github.io` 루트 교체

자세한 이관 순서와 배치 상한은 `MIGRATION_V1.md`를 따른다. 전체 10년치 데이터의 본 이관은 검색·탐색 프로토타입이 승인되기 전에는 시작하지 않는다.
