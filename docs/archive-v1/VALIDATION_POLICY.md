# Sandle Archive v1 — 자율 검증·진행 원칙

상태: 운영 기준 v1  
작성: 2026-09-01

## 목적

GPT, Claude 등 어떤 AI가 작업하더라도 소단계마다 사용자 확인을 반복하지 않고, 담당 AI가 직접 검증·보완한 뒤 다음 단계로 이어가기 위한 공통 기준이다.

사용자는 나중에 전체 결과를 보고 수정 요청을 할 수 있다. 그때 담당 AI가 요청 내용이 어느 단계와 연결되는지 판단하고, 기존 완료 기록을 지우지 않은 채 해당 단계에 새 보완 번호를 추가한다.

## 단계 통과 조건

큰 단계는 아래 항목을 모두 충족하면 `done`으로 바꿀 수 있다.

1. Roadmap에 적힌 핵심 기능이 실제로 연결되어 있다.
2. 문법·정적 로드 검사가 통과한다.
3. 핵심 변환·분류·저장 흐름에 자동 검증이 있다.
4. 가능한 경우 실제 데이터 전체 또는 대표 표본을 통과한다.
5. 누락, 중복, 잘못된 확정, 원본 훼손 여부를 확인한다.
6. 기존 운영 기능과의 호환성을 확인한다.
7. 기능·데이터·스타일·검증 파일을 적절히 분리한다.
8. 버전 또는 캐시 키를 올린다.
9. `WORK_STATUS.md`에 검증 결과, 남은 위험, 완료 시각, 관련 커밋을 남긴다.

## 체크포인트 우선 원칙

단계 전체가 끝나지 않았더라도 검증 가능한 기능 묶음 하나가 끝나면 먼저 체크포인트를 만든다. 체크포인트 이후의 작업은 아직 존재하지 않는 것으로 가정해도 다른 AI가 이어갈 수 있어야 한다.

- 설계만 끝났다면 설계 완료와 미구현 범위를 분리해서 기록한다.
- 구현이 끝났지만 검증 전이라면 `review` 또는 `in_progress`로 유지한다.
- 자동 검증까지 끝난 범위만 `검증됨`으로 적는다.
- 커밋 전 작업은 인계 완료로 보지 않는다.
- 버전·캐시 키와 완료 시각은 배포 체크포인트마다 갱신한다.

## 사용자 확인이 필요한 예외

다음 항목은 담당 AI가 임의로 확정하지 않는다.

- resident/private 자료의 실제 인증 방식과 접근 권한 부여
- 공개 범위를 넓히는 변경
- 원본 문서나 기존 회의록 데이터를 덮어쓰거나 삭제하는 작업
- 운영 루트 전환처럼 이용자가 보는 기본 경로를 크게 바꾸는 작업
- 비용이 발생하는 외부 서비스 또는 계정 연결
- 법적 판단이나 개인정보 처리 기준처럼 사용자 책임 범위를 바꾸는 결정

이외의 UI 문구, 배치, 내부 모듈 분리, 안전한 오류 수정, 검증 보강은 담당 AI가 판단해 진행한다.

## 피드백 반영 규칙

예를 들어 6단계까지 진행한 뒤 사용자가 회의록 변환 화면 수정을 요청한 경우:

- 6단계를 억지로 수정 단계로 기록하지 않는다.
- 영향 범위를 분석해 3단계 보완이면 `3.8 사용자 피드백 반영`을 추가한다.
- 3단계 변경이 5·6단계 데이터에 미치는 영향을 다시 검증한다.
- 현재 진행 위치와 완료 이력을 `WORK_STATUS.md`에 함께 남긴다.

## 검증 기록 형식

```text
단계: 3
검증 시각: YYYY-MM-DD HH:mm:ss KST
자동 검증: 통과/실패
실제 데이터: 회의 N건, Fragment N건
발견·보완: 내용
원본 변경: 없음/있음
호환성: 내용
남은 위험: 내용
다음 단계: 4.1
```
