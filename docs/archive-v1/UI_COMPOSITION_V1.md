# Sandle Archive v1 — UI 조립식 구성 원칙

상태: v1 초안
작성: 2026-09-01

## 목적

Archive v1은 데이터 이관 후에도 화면 구성을 자주 바꿀 수 있어야 한다.
`현재 기준 → 타임라인 → 기록`을 `현재 기준 → 핵심 요약 → 타임라인 → 자료 전체`로 바꾸거나, 2열을 1열로 바꾸는 일이 데이터 재이관이나 대규모 코드수정으로 이어지지 않게 한다.

## 핵심 원칙

1. **데이터와 화면 순서를 분리한다.**
   - `current`, `timeline`, `records`, `summary` 같은 의미 단위는 데이터/렌더링 단위로 유지한다.
   - 어떤 순서로 보여줄지는 별도 layout config에서 정한다.

2. **한 자료를 화면별로 복제하지 않는다.**
   - A안/B안/주제 상세가 같은 Document·Fragment·Event 데이터를 공유한다.
   - 화면을 바꿔도 원본 데이터는 다시 만들지 않는다.

3. **레이아웃 설정은 작은 파일로 분리한다.**
   - 현재 시험 위치: `archive-v1/config/search-layouts.js`
   - A안: `current → timeline → records`
   - B안: `current → summary → timeline → records`
   - 이후 순서 변경은 가능하면 config 변경으로 끝내는 구조를 지향한다.

4. **스타일도 화면별로 분리한다.**
   - 공통: `archive.css`
   - 첫 화면: `home.css`
   - 상세 팝업: `detail.css`
   - 검색 A: `search-a.css`
   - 검색 B: `search-b.css`
   - 한 파일에 기능을 계속 누적하지 않는다.

5. **표시 개수는 데이터 자체가 아니라 layout 설정이다.**
   - 예: A안 관련 기록 6건 미리보기, B안 12건 미리보기.
   - 실제 데이터는 그대로 두고 화면마다 표시량만 조절한다.

6. **자료가 많아질 때의 길이 제한을 기본값으로 둔다.**
   - 화면에서 모든 데이터를 무조건 펼치지 않는다.
   - 미리보기, 전체 보기, 향후 페이지네이션/필터를 조합한다.

7. **현재/과거 판정과 화면 위치를 섞지 않는다.**
   - `current` 여부는 데이터 의미다.
   - 그 정보를 첫 번째에 둘지 두 번째에 둘지는 UI 선택이다.

## 1.7 시험 구조

`search-layouts.js`에서 A/B의 section 순서와 preview 개수를 별도로 둔다.

- A: `current → timeline → records`
- B: `current → summary → timeline → records`

1.7에서는 B를 기본 검색화면으로 보여주고 A/B를 같은 검색어로 전환해서 비교할 수 있게 한다.

## 앞으로의 방향

1단계에서 최종 검색 구성이 정해지면 현재 프로토타입의 중복 렌더링 코드를 정리해 공통 section renderer로 합친다.
그 이후에는 다음 변경이 데이터 재이관 없이 가능해야 한다.

- section 순서 변경
- section 숨김/추가
- 1열/2열 전환
- 미리보기 개수 변경
- 모바일 순서 별도 지정
- 요약 표시 방식 변경
- 전체 목록을 펼치기/별도 페이지/페이지네이션 중 하나로 교체

중요한 기준은 **화면 개편이 데이터 구조 변경의 이유가 되지 않게 하는 것**이다.
