## 3단계 시작 판단

사용자 목표는 기존 회의 작성 기능을 새로 만드는 것이 아니라 **이미 만들어진 회의록·기록을 더 보기 쉽고 연결되게 정리하는 것**으로 재확인함.

따라서 3단계는 기존 `minutes` 작성 화면을 다시 만드는 방향이 아니라 다음 흐름으로 진행한다.

`기존 회의록 데이터 읽기 → 회의 1건을 Document로 변환 → 안건별 Fragment로 분해 → 기존 태그·내용을 우선 활용해 주제 후보 생성 → 의결·후속조치 구조화 → 관리자 검토로 보내기`

### 3단계에서 건드리지 않는 것

- `SandleAPT/minutes` 기존 작성·저장 UI
- 현재 회의록 출력/PDF 흐름
- Claude가 예약한 입대의 데이터 9건
- 운영 루트 `index.html`

### 3단계에서 만들 것

- 현재 `minutes/data-index.json` 및 연도별 정적 회의 데이터 읽기
- 회의 선택/불러오기 화면
- 회의 → Document / 안건 → Fragment 변환 미리보기
- 의결사항·후속조치·표결 요약 구조화
- 기존 안건 태그가 있으면 우선 사용, 자동 추정은 후보로 구분
- 변환 결과를 2단계 분류 검토 흐름으로 보내는 연결
- 기존 회의록 앱 원본으로 돌아가는 링크
- 1페이지 출력은 기존 minutes 출력물을 원본으로 유지하고 Archive가 이를 침범하지 않는 구조 확인
