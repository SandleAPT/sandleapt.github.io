# 회의자료 작성 도구

## 목적

동별대표자가 의결안건과 보고사항을 구분해 표지와 본문 A4 2장으로 제출할 수 있게 하는 작성 도구다.

주소:
- 포털: `/#proposalView`
- 직접 열기: `/agenda-proposal/`

## 화면

- 왼쪽: 자료 유형 선택, 입력 폼, 클라우드 회의자료 목록
- 오른쪽: 별지 제7호 구조를 반영한 A4 2장 미리보기(표지 + 본문)
- 의결안건: 의안번호, 의결년월일, 제목, 제출자, 제출년월일, 의결주문, 제안이유, 주요내용, 비용추계서, 참고사항
- 보고사항: 보고번호, 보고일자, 제목, 보고자, 작성일, 보고요지, 보고배경, 주요내용, 비용·관리비 영향, 참고사항
- 향후 일정·후속사항은 입력·출력에서 제거했다. 기존 저장값은 숨김 필드로 보존한다.
- 클라우드 읽기는 15초 제한으로 최대 3회 시도하며, 목록 옆에 진행·실패 상태를 표시한다. 저장·삭제는 자동 재시도하지 않는다.
- 의안번호와 보고번호는 같은 회의일·같은 자료 유형 안에서 저장 순서대로 각각 자동 배정한다.
- 클라우드 목록의 `↑`·`↓`로 같은 그룹 안의 순서를 바꾸면 화면 번호를 즉시 다시 계산한다. 중간 자료를 삭제해도 뒤 번호가 자동으로 당겨진다.
- 보고사항에 `의결한다`, `승인한다`, `선정한다`, `확정한다`, `변경한다`, `집행한다` 같은 결정 표현이 들어가면 의결안건 분리 여부를 확인하도록 경고한다.
- 어려운 행정용어보다 주민이 바로 이해할 수 있는 말로 작성하도록 안내한다.
- `- `로 시작한 줄은 미리보기에서 목록으로 표시한다.

- 참고사항의 첨부 목록은 파일 순서대로 `※ 첨부1: 파일명`, `※ 첨부2: 파일명`으로 표시하며 제거 시 번호를 다시 매긴다.

## A4 2장 원칙

- 표지 1장과 본문 1장을 각각 A4 세로로 고정한다.
- 본문이 길어지면 글자 크기와 줄 간격을 정해진 범위 안에서 자동으로 조금 줄인다.
- 그래도 본문 한 장을 넘으면 내용을 줄이도록 안내하고 인쇄 버튼을 잠근다.
- 출력 디자인은 기존 회의록의 muted gray-green 톤과 얇은 이중선을 이어 쓰되, 제목·소제목 앞 세로 강조선은 쓰지 않는다.

## 저장과 개인정보

- 초안은 작성한 브라우저의 `localStorage`(`sandle_agenda_proposal_v1`)에만 자동 저장한다.
- 명시적 `문서 저장 / 불러오기 / 삭제`는 기존 비공개 자료 Apps Script 저장소를 사용한다.
- 의결/보고 유형과 내부 정렬키, 본문, 첨부 PDF/JPG/PNG/HWP를 한 레코드에 함께 보관한다.
- 기존 v1 클라우드 문서와 로컬 초안에 자료 유형이 없으면 의결안건으로 해석하고, 기존 의안번호를 최초 정렬 기준으로 사용한다.

## 2026-09-20 리디자인

- 산들마을 관리규약 별지 제7호의 의안번호·의결년월일·의결사항·제목·제출자·제출년월일 구조를 표지에 반영했다.
- 표지는 3열×2행 정보표(의결사항 2행 병합), 흰색 제목 영역, 제출자 표로 구성한다.
- 본문은 의결주문 → 제안이유 → 주요내용 → 비용추계서 → 참고사항 순서이며 소제목 앞 세로색 막대를 제거했다.
- 각 페이지 상단의 작은 `회의 표기`는 선택 입력이며, 기존 회의록처럼 오른쪽 위에 작게 노출한다.
- 색상은 기존 회의록 수준의 낮은 채도 녹회색과 중성 회색을 사용한다.


## 2026-09-20 입력 단순화

- `의안번호`는 문자열을 직접 쓰지 않고 1~50호 숫자 선택으로 입력한다. 미리보기에서는 `제 N 호`로 표시한다.
- 사용자가 파악하기 어려운 `회의차수` 입력은 제거했다. 의결년월일에는 날짜만 표시하고, 회의 정보는 선택 입력인 `회의 표기`로 상단에 보여준다.
- 기존 저장 문서의 `제 1 호` 같은 의안번호 문자열은 숫자를 추출해 자동 호환한다.

## 2026-09-20 회의 표기 자동화

- 자유입력 `회의 표기`를 제거하고 `회의 구분`에서 `정기`/`임시`만 선택하도록 단순화했다.
- 현재 입주자대표회의 기수는 제6기로 고정하고, 의결년월일에서 연도·월을 자동으로 가져와 `제6기 YYYY년MM월 정기|임시 입주자대표회의`를 만든다.
- 회의 구분을 아직 선택하지 않았으면 기수·연월만 표시하고, 의결년월일이 비어 있으면 상단 회의 표기도 숨긴다.
- 기존 저장 문서의 `meetingHeader`에 `정기` 또는 `임시`가 들어 있으면 새 `meetingType`으로 자동 변환한다.

## 2026-09-20 클라우드 보관함 전환

- 명시적 `문서 저장 / 불러오기 / 삭제`는 브라우저 IndexedDB 대신 기존 비공개 자료 Apps Script 저장소를 사용한다.
- 저장소 주소는 기존 `sandle_private_url`, 수정용 비밀번호는 `sandle_admin_key`를 재사용한다. 주소는 기기마다 최초 1회 연결한다.
- 제안서 본문과 첨부 PDF/JPG/PNG/HWP를 한 클라우드 레코드에 함께 보관한다. 다른 PC에서 불러오면 첨부도 복원되어 출력할 수 있다.
- 안전 한도는 레코드 JSON 약 8MB. 그보다 크면 큰 파일을 나누도록 안내한다.
- 작성 중 자동초안만 `localStorage`에 남겨 브라우저 종료/오류에 대비한다. 명시적으로 저장한 문서의 기준은 클라우드다.

## 2026-09-20 의결·보고 분리와 자동 순번

- 화면 상단에서 `의결안건 / 보고사항`을 먼저 선택한다.
- 의결안건은 관리규약 별지 제7호 구조를 유지한다. 보고사항은 같은 디자인 안에서 `보고요지 / 보고배경 / 주요내용 / 비용·관리비 영향 / 향후 일정·후속사항 / 참고사항`으로 전환한다.
- 의결번호와 보고번호는 서로 섞지 않고, 같은 회의일 안에서 유형별로 각각 1호부터 매긴다.
- 실제 저장 순서는 `orderKey`로 보존하고, 보이는 번호는 현재 정렬 결과에서 계산한다. 따라서 순서 변경이나 삭제 때 여러 문서를 동시에 덮어쓰지 않아도 번호가 연속으로 유지된다.
- 새 문서는 같은 회의일·유형의 마지막에 붙는다. `↑`·`↓`는 이동할 문서 한 건의 정렬키만 갱신한다.
- 새 클라우드 레코드 제목에는 유형·회의구분·정렬키 메타데이터를 넣어 목록 조회만으로 순서를 구성한다. 과거 `[안건제안서]` 레코드는 최초 목록 조회 때 본문을 읽어 호환한다.
- 보고사항에서는 공사·재원용 `절차 확인` 카드를 숨기고, 결정형 표현을 감지하면 의결안건 분리 경고를 표시한다.

## 2026-09-20 등록·수정 구분

- 새 문서는 `새로 등록`, 기존 문서는 `수정`과 `삭제` 버튼을 표시한다. `새 문서`로 별도 작성을 시작한다.
- 초안에 저장 문서 ID·생성시각·저장소 주소를 함께 보관하여 새로고침 후에도 같은 문서를 수정한다. 구형 초안은 ID가 없으므로 목록에서 한 번 불러와야 한다. 제목으로 임의 매칭하지 않는다.
- 새로고침 후 수정 저장은 기존 첨부를 먼저 읽어 보존한다. 첨부를 삭제하려면 목록에서 다시 불러온 후 제거한다. 읽기 실패 시 덮어쓰지 않는다.
- 검증: `node agenda-proposal/tests/save-document.test.js` (신규 ID, 수정 ID 유지, 새로고침 연결, 기존 HWP 보존).

## v446 자동 연결

인증 서버의 수정 verify 응답 privateStoreUrl을 저장하여 기기별 주소 입력을 없앤다. 최초 등록은 기존 연결 기기의 수정 로그인으로 수행한다. 실제 Apps Script 서버 배포가 선행되어야 하며 현재 대기 중이다.
