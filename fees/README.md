# 산들마을 관리비 데이터 운영 규칙

이 폴더는 산들마을 관리비 원자료를 장기간 누적·검색·비교·분석하기 위한 공개 데이터 저장소다. 작업 도구나 담당자가 바뀌어도 아래 규칙을 유지한다.

## 파일 역할

- `data.json`: 전체 자료목차, 스키마 버전, 연도파일 목록, 값·비고·비교 의미
- `categories.json`: 항목코드 사전. 같은 비용 성격은 연도와 원문 명칭이 달라도 같은 코드를 사용
- `data-YYYY.json`: 해당 연도의 월별 원자료(부과총괄 4쪽)와 원문표(14쪽 관리외 비용·관리외 수익, 15쪽 예금 잔액)
- `detail-YYYY.json`: 해당 연도의 항목별 산출내역(원문 5~13쪽). 계약업체·계약기간·산출 근거·면적별 부과내역·수선 건별 내역을 표 단위로 보존한다. 부과총괄과 별도 파일로 두는 이유는 크기(월당 약 20개 표)와 로딩 분리 때문이다
- `reviews.json`: 자동점검 정책, 회의록·규약 대조, 분석 메모. 화면의 '규약 위반 확인' 표시는 이 파일의 `confirmed` 값으로만 켠다
- `decisions.json`: 의결 대조 계층. 비용 발생·변동을 공개 회의록 의결과 건별로 대조한 결과(`findings`)와 근거 의결 사전(`decisions`), 항목 분류(`policies`), 대조 완료 범위(`reviewedThrough`). '의결 대조' 탭이 이 파일만 읽는다
- `index.html`: 조회 화면. 원자료를 읽어 비교값과 그래프를 계산

PDF 원본은 저장소에 올리지 않는다. 출처 파일명과 SHA-256, 원문 쪽 번호를 `sources`에 기록한다.

## 원문(관리비부과명세서) 구성

네이버카페 인쇄본 기준 18쪽이며 원문 쪽 번호는 15쪽까지다.

| 원문 쪽 | 인쇄 쪽 | 내용 | 저장 위치 |
| --- | --- | --- | --- |
| 표지 | 2 | 산출기간(관리비·난방급탕·전기·수도), 납부기한, 연체요율 | `detail-YYYY.json` documents[].cover |
| 1~3 | 3~5 | 공지사항(매월 반복되는 안내문) | 옮기지 않음 |
| 4 | 6 | 관리비 부과 총괄표 | `data-YYYY.json` lineItems·groupTotals·monthlyTotals |
| 5~13 | 7~15 | 1. 일반관리비 ~ 18. 주차수입 항목별 산출내역·부과내역 | `detail-YYYY.json` documents[].sections |
| 14 | 16 | 관리외 수익, 관리외 비용 | `data-YYYY.json` supplementalTables (`management-income`, `management-expense`) |
| 15 | 17 | 예금 잔액 현황 | `data-YYYY.json` supplementalTables (`deposit-balance`) |

원문은 스캔 이미지라 `pdftotext`가 통하지 않는다. `pdftoppm -r 150 -png`로 쪽을 그려 눈으로 옮기고, 작은 글씨(수선유지비 비고)는 `-r 250`으로 잘라 다시 본다.

## 절대 지켜야 할 분리 원칙

1. 원문 금액은 `data-YYYY.json`·`detail-YYYY.json`에 원문 그대로 저장한다.
2. 원문 비고는 `sourceNotes` 또는 해당 원문표 행의 `note`에 의미를 바꾸지 않고 저장한다. 원문 각주(♣ ▶)는 `sections[].notes`에 그대로 둔다.
3. 검토자의 판단·의혹·규약 대조·자동점검은 `reviews.json`에만 저장한다.
4. 원문 비고가 없거나 아직 추출하지 않았으면 내용을 만들어 넣지 않는다.
5. 기존 값을 정정할 때는 출처와 정정 사유를 확인하고 `updatedAt`을 갱신한다.
6. 원문끼리 맞지 않는 값(인쇄된 단가와 나눗셈 값의 차이, 면제세대 수 합계 등)은 원문대로 옮기고 `reviews.json`의 `reconciliations`에 사유를 남긴다.
7. 개인정보는 옮기지 않는다: 예금 계좌번호, 인쇄본 하단의 카페 닉네임·동호수. 원문 비고에 있는 수선 위치 표기(예: 213동 902호 스프링클러 누수)는 공고문 그대로 둔다.

## 항목과 기간의 키

- 기간: `YYYY-MM`
- 부과총괄 행: `period + sourceTable + categoryCode`
- 그룹 합계: `period + sourceTable + sourceName`
- 원문표: `period + sourceTable`
- 산출내역 섹션: `period + no` (원문 번호 "1"~"18", "7-1", "17-1")
- 같은 성격의 항목은 모든 기간에 같은 `categoryCode`를 사용한다.
- 원문 명칭은 `sourceName`에 별도 보존한다.

새 항목이 나오면 기존 `categories.json`의 코드·별칭을 먼저 확인한다. 정말 새로운 비용 성격일 때만 새 코드를 추가한다.

## detail-YYYY.json 표 종류

- `breakdown`: 항목·금액·내역 표(일반관리비 인건비 등). `rows[].group`이 원문의 세로 묶음
- `allocation`: 면적별 부과액 표. `scope`는 `allocationScopes` 키(전체 1,171 / 분양+조기분양 940 / 임대 231 / 분양 517 / 조기분양 454·423·31 / 음식물 1,143). `perUnit`=세대당 금액, `total`=타입 합계, `adjustment`=부과차액
- `split`: 내역별 금액을 분양·임대로 나눈 표(승강기유지비·수선유지비). 수선유지비는 건별 한 행
- `composition`: 발생금액 구성(용역비·연차·퇴직적립·휴가비)
- `usage`: 사용량·금액 표(난방·급탕·전기·수도)
- `elevatorByBuilding`: 동별·호기별 승강기 전기료
- `insurance`: 보험 종류별 당월 금액·총액·회차
- `parking`: 주차수입 집계

## 비교 규칙

- 전월 대비: 바로 앞 달의 같은 `categoryCode`와 비교
- 전년 동월 대비: 1년 전 같은 달의 같은 `categoryCode`와 비교
- 비교 대상 기간이나 항목이 없으면 `자료 없음`으로 표시하며 0원으로 간주하지 않는다.
- 비교값은 원자료에서 화면이 계산한다. 데이터 파일에 중복 저장하지 않는다.
- 관리외 비용은 부과총괄과 합치지 않고 별도 계열로 비교한다.
- 관리외 비용에서 원문 항목명이 같더라도 비고가 서로 다른 비용 성격을 명확히 나타내면 별도 계열로 비교한다. 현재 `공동체활성화비용`은 비고의 `작은도서관`과 `경로당`을 각각 독립 계열로 표시하며, 비고가 없는 행은 어느 쪽에도 임의로 합치지 않는다.
- 전체 상세내역의 접이식 표는 원문 쪽 번호 오름차순으로 표시한다. 여러 쪽에 걸친 항목은 시작 쪽을 기준으로 두고, 같은 쪽에서는 원문 표의 순서를 유지한다.

## 원문 비고 구조

부과총괄 행에 비고가 있을 때:

```json
"sourceNotes": [
  {
    "text": "원문 비고",
    "sourcePage": 14,
    "sourceField": "비고"
  }
]
```

관리외 비용처럼 원문표에 비고 열이 있으면 `supplementalTables[].rows[].note`에 저장한다. 화면의 월별 흐름은 이 비고를 해당 월·항목 금액과 함께 표시한다.

## 월 자료 추가 순서

1. PDF의 부과기간·게시일(인쇄본 1쪽의 카페 게시 일시)·쪽 수·SHA-256을 확인한다.
2. `sources`에 출처 메타데이터를 추가한다.
3. `monthlyTotals`, `lineItems`, `groupTotals`를 원문 열 구조대로 추가한다. 원문의 `-`는 0으로 적는다.
4. 원문 14쪽의 관리외 수익·관리외 비용과 비고, 15쪽의 예금 잔액을 `supplementalTables`에 추가한다.
5. 원문 5~13쪽의 항목별 산출내역을 `detail-YYYY.json`에 섹션 단위로 추가한다.
6. 새 항목코드가 필요한지 `categories.json`에서 확인한다.
7. 검산 스크립트를 돌린다(아래 '필수 검산'). 원문 내부 불일치는 `reviews.json`의 `reconciliations`에 남긴다.
8. `data.json`의 연도 범위·월 수·상태와 각 파일의 `updatedAt`을 갱신한다.
9. 의결 대조: 새 달의 큰 변동·신설 항목과 관리외 비용 발생 건을 공개 회의록 의결과 대조해 `decisions.json`의 `findings`에 추가하고 `reviewedThrough`를 올린다(대조 전에는 화면이 자동으로 '대조 전'으로 표시).

## 새 연도 추가

기존 연도 파일을 합치거나 덮어쓰지 않는다. `data-YYYY.json`·`detail-YYYY.json`을 새로 만들고 `data.json.years`에 한 줄 추가한다. 화면은 연도파일 목록을 읽어 연도·월 선택과 장기 비교를 자동 구성한다.

## 필수 검산

검산 스크립트 `fees/tools/check-fees.ps1 -Period YYYY-MM -Prev YYYY-MM`(PowerShell 5.1. 한글 키를 쓰므로 UTF-8 BOM을 유지한다)이 확인하는 것:

- JSON 파일 전체 파싱 성공
- 같은 기본키의 중복 없음, 항목코드가 사전에 있음
- 부과총괄: 행 합계 = 당월부과액 행, 그룹 합계 = 해당 그룹 행 합계, 행마다 `입주자분+LH분=당월부과`, `당월부과−발생=부과차액`, `당월부과−전월부과=증감`, `previousBilled`가 직전 월 `billed`와 연결
- 관리외 수익·비용: `전월잔액 + 당월발생액 = 당월잔액`의 행별·합계별 연속성, 전월잔액이 직전 월 당월잔액과 연결
- 예금 잔액: 행 합계 = 합계
- 산출내역: 섹션 금액 = 부과총괄 발생금액, 면적별 부과표의 `세대수×세대당=합계`·행 합계=합계·`합계−발생=부과차액`·세대수=범위 세대수, 분양·임대로 나뉜 부과표는 합쳐서 부과총괄 당월부과와 대조, 내역·구성·보험·주차·승강기 표의 행 합계, 섹션 금액 합 = 당월부과액
- `sourceNotes`와 `reviews.json`의 분석 메모가 섞이지 않았는지 확인

## 공개 버전

상단 버전은 GitHub 누적 커밋 순번에 맞춰 1씩 올린다. 표시 형식은 `v숫자 · YYYY.MM.DD HH:MM:SS 갱신`이며 한국시간을 사용한다. 화면 데이터 캐시 키는 `index.html` 상단의 `CACHE_V` 상수 한 곳에서 같은 버전으로 갱신한다.

## 현재 입력 범위

- 2026년 1~7월 부과총괄표
- 2026년 1~7월 관리외 비용 및 원문 비고
- 2026년 1~7월: 원문 전체(항목별 산출내역 각 20개 섹션, 관리외 수익, 예금 잔액)
- 부과총괄 항목코드 29개
